# Handoff: SalesDrive dashboard

## Назначение

Проект — PHP-дашборд для аналитики заказов SalesDrive: сводные показатели,
менеджеры, города, товары, мотивация и настройки. Данные хранятся в MariaDB;
заказы и метаданные синхронизируются с SalesDrive API. Прошлый сервер Contabo
был утрачен, поэтому этот репозиторий и SQL-дампы — основа восстановления.

## Структура

- Корень — родительский Git-репозиторий. В нём `dashboard` — **git submodule**.
- `dashboard/` — самостоятельный репозиторий приложения, ветка `main`.
- `dashboard/html/dashboard/` — веб-интерфейс и его PHP API.
- `dashboard/private/` — конфигурация, импорт, синхронизация и миграции БД.
- `dashboard/private/migrations/` — миграции схемы заказов и каталога.
- `dashboard/tools/` — диагностические скрипты для данных заказов.

## Ключевые компоненты

- `private/sync_orders.php` — инкрементальная загрузка заказов SalesDrive по
  `update_at`; состояние хранится в `private/sync_orders_state.json`.
- `private/import.php` и `private/backfill_orders_from_json.php` — импорт и
  дозагрузка истории.
- `private/salesdrive_order_mapper.php` — нормализация ответа SalesDrive и
  UPSERT заказов.
- `private/import_products_from_xlsx.php` и `private/product_catalog_importer.php`
  — импорт каталога из XLSX; зависимость — `phpoffice/phpspreadsheet`.
- `html/dashboard/analyze_orders.php` — пересобирает
  `/var/www/private/analytics_ready.json`, который читают страницы аналитики.
- `html/dashboard/{index,cities,products,motivation,settings}.php` — экраны UI.
- `html/dashboard/i18n.js` — RU/UK-переключатель для интерфейса. Он не должен
  переводить товары, группы, статусы и другие данные из БД.

## Развёртывание / восстановление на сервере

1. Установить PHP с расширениями PDO MySQL, MariaDB/MySQL, Composer и зависимости
   из `dashboard/private/composer.lock` (`composer install` в `private/`).
2. Создать БД и импортировать `salesdrive.sql`, затем `products_catalog.sql`.
3. Применить миграции `001_add_salesdrive_order_fields.sql` и
   `002_create_products_catalog.sql` (они идемпотентны там, где это возможно).
4. Создать новый локальный `dashboard/private/config.php` с новыми реквизитами
   БД и API. Не копировать старые ключи как есть.
5. Разместить веб-каталог и проверить пути, которые сейчас жёстко используют
   `/var/www/private/`.
6. Настроить cron для `private/sync_orders.php`; после первичной загрузки
   запустить `html/dashboard/analyze_orders.php` для генерации
   `analytics_ready.json`.
7. Проверить главную страницу, отчёты по городам/товарам и импорт XLSX.

Nginx/Apache, cron, SSL, логи и любые файлы вне репозитория не сохранились — их
нужно воссоздать на новом сервере.

## Безопасность: обязательно до запуска

В проектной папке обнаружены сохранённые секреты (в том числе в конфигурации и
вспомогательных локальных файлах). Считать их скомпрометированными:

1. Отозвать/перевыпустить GitHub token, ключ SalesDrive и прочие API-ключи.
2. Сменить пароль БД и сохранить новые значения только в локальном `config.php`
   или безопасном менеджере секретов.
3. Добавить секретные файлы в `.gitignore`, при необходимости предоставить
   `config.example.php` без значений.
4. Проверить историю Git на случай, если секреты когда-либо были закоммичены.

## Перенос на новый компьютер

1. Дождаться синхронизации этой папки OneDrive, включая скрытую `.git` и
   вложенный `dashboard/.git`.
2. На новом ПК войти в тот же аккаунт, установить Git, PHP/Composer (если нужна
   локальная разработка) и открыть ту же синхронизированную папку в Codex.
3. Проверить `git status` в корне и `git -C dashboard status` до любых изменений.
4. Открыть этот файл в новом чате Codex и попросить начать с раздела
   «Что проверить сначала».

История Codex-задач не должна быть единственным источником контекста; этот файл
предназначен именно для независимого продолжения работы на новом устройстве.

## Что проверить сначала

1. Есть ли оба SQL-дампа после синхронизации OneDrive и совпадают ли размеры.
2. Инициализирован ли submodule `dashboard` и соответствует ли его `main`
   ожидаемому commit `9c2ad21` или более новому.
3. Нет ли в рабочем дереве секретов, готовых попасть в коммит.
4. Доступны ли новые реквизиты SalesDrive и БД; без них нельзя безопасно
   продолжить синхронизацию.
5. После восстановления сервера — корректность cron, доступность API и генерация
   `analytics_ready.json`.
